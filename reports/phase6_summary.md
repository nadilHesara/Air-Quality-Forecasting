# Phase 6 — Model Improvement: summary & verdict

**Goal:** move meaningfully past the persistence baseline (was +4.5% MAE), *or*
prove the gap is intrinsic and frame it honestly — plus ship prediction
intervals. This is the consolidated write-up; each sub-experiment has its own
report (linked below) and its runs are logged to MLflow.

All experiments are reproducible offline from `data/training_data.parquet` via
`python -m experiments.<name>`. **Model selection (features, tuning) used the
train pool only**; the held-out test window (`2026-03-15 → 2026-06-12`, 90 days)
was scored once, at the end.

## Verdict

**The remaining gap over persistence is largely intrinsic — and we now ship
calibrated prediction intervals.**

Daily-mean PM2.5 has lag-1 autocorrelation ≈ **0.83**: today's value already
captures almost all the predictable signal, so the only headroom above
persistence is anticipating the day-over-day *move*, which is close to noise.
Every avenue we tried confirms this:

| Avenue | Result |
|---|---|
| **6.1 Error analysis** | Model wins only **53%** of days; on *calm* days persistence is actually better (it copies today), the model's edge is confined to *big-move* days, and it **under-predicts spikes** (mean residual −0.43 at high levels). |
| **6.2 Feature experiments** | All 8 candidates passed the leakage test; the best single ones (wind sin/cos, extra lags) shaved ≤0.07 off CV MAE but **cancelled when combined** (Δ ≈ 0). No robust point-forecast gain. |
| **6.3 Optuna tuning** | Improved *CV* MAE (5.00 → 4.67) and stability, but on the held-out test the tuned config **lost MAE** (3.31 → 3.37) while **improving RMSE** (4.53 → 4.44). The shipped hand-picked params are already at the plateau for MAE. |
| **6.4 Model comparison** | Ridge, LightGBM, XGBoost, and SARIMAX all land within a **~5% MAE band** of each other and of persistence. When four model families converge, the ceiling is the data, not the model. |
| **6.6 Multi-horizon** | +1/+2/+3-day skill over persistence is small and **noisy** (+4.5% / −1.0% / +7.2%), not a clean trend — same thin-signal story. |

So we did **not** manufacture a large, dubious point-MAE win. Instead the
honest deliverables are:

1. **A documented, defensible characterisation** of why the gap is small.
2. **Better tail behaviour** — LightGBM leads on RMSE (fewer big misses on spike
   days), which is why it stays the production model.
3. **Calibrated prediction intervals (6.5)** — the real value-add the error
   analysis pointed to.

## 6.5 Prediction intervals (shipped to serving)

The production model now bundles three LightGBM quantile regressors
(`objective="quantile"` at p10/p50/p90). Vanilla quantile LGBM on ~1k rows
under-covers badly (80% nominal → **67.8%** empirical), so we apply
**split-conformal calibration** (Romano et al. 2019): quantile offsets are
learned on a held-out *tail of the train pool*, never the test set.

| Metric | Before calibration | After (shipped) |
|---|---:|---:|
| Empirical coverage of the 80% band | 67.8% | **80.0%** |
| Mean interval width | 9.28 | 13.02 µg/m³ |

The band is asymmetric (wider on the upside), correctly reflecting PM2.5's
right-skew and the spike-risk the error analysis flagged. The point forecast
falls inside the band on **100%** of test rows. `GET /predict` now returns
`pm25_lower` / `pm25_upper` / `interval_coverage`, and the dashboard shows the
range.
